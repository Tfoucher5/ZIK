# v2.6.0 — Succès, séries de jeu, scores partageables & mode maintenance

## Contexte

Version orientée **rétention** et **croissance** : donner aux joueurs des raisons de revenir chaque jour (séries, succès) et des outils pour faire venir leurs amis (score partageable). S'y ajoutent deux tâches du backlog Notion : le mur d'actualité et le mode maintenance.

## ⚠️ Action requise avant mise en production

Deux migrations SQL doivent être appliquées sur le projet Supabase ZIK (`fbeubmwhxytniohodlgr`) :

1. `supabase/migrations/20260610_achievements_streaks_game_results.sql`
2. `supabase/migrations/20260610_site_settings.sql`

Les deux sont **additives** (aucune donnée existante modifiée). **Tant qu'elles ne sont pas appliquées, le site fonctionne exactement comme avant** : tout le nouveau code échoue en silence (pas de succès, pas de partage, pas de maintenance — mais zéro crash).

`SUPABASE_SERVICE_KEY` doit être présent dans l'environnement serveur (déjà le cas en prod) : les écritures `user_achievements` / `game_results` / `site_settings` passent par le client service role.

## Ce qui change

### 🏅 Succès (achievements)

- 10 succès seedés en base : `first_win`, `wins_count`, `podium_count`, `streak_days`, `win_streak`, `big_game`, `perfect_game`, `score_total`, `games_played`, `early_adopter` (manuel, à débloquer via SQL/admin).
- Les succès à paliers (bronze/argent/or) portent leurs cibles dans `achievements.tiers` (jsonb) — modifiables en base sans toucher au code.
- Vérification serveur en fin de partie **classique uniquement** (pas de QCM, cohérent avec `update_player_stats`), pour les joueurs connectés non-invités.
- Seuils calibrés sur l'échelle de points réelle du mode classique (1 pt + bonus vitesse ≤ 2) : `big_game` = 40 pts/partie, `score_total` = 500/2 500/10 000.
- `perfect_game` : artiste + titre (+ feats/extras) trouvés sur toutes les manches, minimum 5 manches.
- Toast de déblocage en jeu (file d'attente, auto-dismiss 4 s) via l'event Socket.io `achievements_unlocked`.
- Profil (perso + public) : panneau `AchievementsPanel` avec compteur X/Y, filtres par catégorie, progression par palier. Rendu uniquement si les tables existent.

### 🔥 Séries de jeu (streaks)

- Nouvelles colonnes `profiles` : `current_streak`, `best_streak`, `last_played_date`, `win_streak`, `best_win_streak` (+ `featured_achievements` réservé pour l'épinglage futur).
- RPC `update_player_streaks(p_user_id, p_won)` : calcul atomique côté Postgres, fuseau **Europe/Paris**. Une victoire = 1er avec ≥ 2 joueurs.
- Affichées en haut du profil avec records.

### 📤 Score partageable

- Table `game_results` (SELECT public) : un enregistrement par joueur connecté en fin de partie classique.
- Event Socket.io `game_result_id` → bouton **"Partager mon score"** sur l'écran de fin (Web Share API sur mobile, copie de lien sinon).
- Page publique `/results/[id]` : carte score (pseudo, points, rang, room, succès débloqués) + CTA "Tu fais mieux ?" + meta OG dynamiques. `noindex` pour éviter le duplicate content.

### 🗞️ Page Nouveautés (`/nouveautes`)

- Mur d'actualité chronologique (tâche Notion), contenu dans `src/lib/news.js` (à enrichir à chaque release).
- Lien dans le footer + entrée sitemap. Indexée SEO.

### 🔧 Mode maintenance

- Table `site_settings` (clé/valeur jsonb), entrée `maintenance` = `{ enabled, message }`.
- `hooks.server.js` : si activé, page 503 stylée pour tout le site **sauf** `/admin` et `/api/admin`. Cache 15 s, fail-open si la table n'existe pas.
- Dashboard admin : section MAINTENANCE_MODE (toggle + message ≤ 500 car.), action loguée dans `admin_audit_log`.

### 💬 Chat en jeu

- Fenêtre déplaçable (drag sur l'en-tête) et redimensionnable horizontalement (bord gauche), desktop uniquement (> 640 px).
- Position et largeur mémorisées en `localStorage` (`zik_chat_pos`, `zik_chat_w`).
